Privacy Policy

LabWorx Applications • Effective Date: September 20, 2026

This Privacy Policy governs the mobile software applications developed and published by LabWorx ("we", "us", or "our"), including LabWorx Virtual Buttons, LabWorx Managed Config Demo, LabWorx LostMode, and any utility applications distributed via Google Play and Managed Google Play.

1. General Principle: Zero Remote Data Collection

All LabWorx applications operate with a strict Zero Remote Data Collection architecture:

  • No Personal Data Harvesting: We do not collect, process, record, profile, transmit, or monetize any personal identifiable information (PII), device identifiers, or biometric data.
  • No Network Transmission: Our applications do not request or declare the android.permission.INTERNET permission in their manifests and function completely offline.
  • No Third-Party SDKs: Our codebases contain zero third-party software development kits (SDKs), advertising networks, telemetry monitors, or remote crash reporters (e.g., no Firebase, AdMob, or Sentry).

2. User Accounts & Data Deletion Policy

In compliance with Google Play Developer Policies regarding account creation and user data retention:

  • No Account Creation: LabWorx applications do not offer, require, or support account registration, authentication credentials, or user profile creation.
  • Account Deletion Exemption: Because no accounts or remote user profiles are maintained, no account deletion mechanisms or web deletion request forms are required.
  • Local Data Removal: Any operational values stored on the device within an application's private sandbox (e.g., Jetpack DataStore preferences) can be deleted at any time by clearing application data via Android Settings > Apps > [App Name] > Storage > Clear Data, or by uninstalling the application.

3. Application-Specific Disclosures & Permissions

Application Disclosure

LabWorx Managed Config Demo

A technical evaluation and demonstration utility for testing Android Managed Configurations delivered via Enterprise Mobility Management (EMM/MDM) systems.

Local Data Handling

The application processes three configuration attributes solely on the local device:

  • User Name: Processed locally to display user identification.
  • Email Address: Processed locally to populate enterprise account testing fields.
  • Serial Number: Processed locally to identify hardware/software test assets.

Permissions & Architecture

  • Permissions: Requests zero system permissions in its manifest (no INTERNET permission, no runtime permissions). It cannot connect to external networks or access sensitive device hardware (such as cameras, location, or microphone).
  • Enterprise Managed Configurations: Policies deployed by an IT administrator are received locally via Android's native RestrictionsManager framework and the ACTION_APPLICATION_RESTRICTIONS_CHANGED broadcast. No configuration data or management events are transmitted to external servers.
  • Sandbox Data Persistence: User preferences and synchronization timestamps are stored strictly on the device using Jetpack DataStore in isolated application storage. Data is purged upon application uninstallation.
Application Disclosure

LabWorx Virtual Buttons

An assistive utility providing on-screen software replacements for hardware buttons (such as lock screen toggles and media volume controls), designed for users with impaired motor functions or devices with malfunctioning physical keys.

AccessibilityService API Disclosure (Google Play Notice)

  • Scope & Purpose: The application uses the Android Accessibility Service API (VirtualAccessibilityService) solely to trigger the system-level screen lock action (GLOBAL_ACTION_LOCK_SCREEN).
  • No Content Inspection or Logging: Configured explicitly with canRetrieveWindowContent="false". It does not read, intercept, monitor, inspect, log, or transmit on-screen text, gestures, keystrokes, personal communications, or user interactions.
  • No Audio or Surveillance: Never used for audio recording, call recording, background surveillance, remote access, or bypassing system security controls.
  • Prominent Consent: Displays an in-app prominent disclosure explaining this capability before guiding the user to system settings to voluntarily enable the service.

Additional Permissions & Offline Execution

  • Quick Settings Tiles (BIND_QUICK_SETTINGS_TILE): Used exclusively to display user-controlled "Screen Lock" and "Media Volume" tiles in the Android notification shade.
  • Offline Execution: Operates completely offline with zero network permissions and zero tracking SDKs.
Application Disclosure

LabWorx LostMode

An enterprise kiosk utility designed to display administrative recovery details and contact notices when a managed handset is placed in lost status.

  • Permissions: Requests zero runtime or system permissions in its manifest (including no INTERNET permission).
  • Volatile Memory (RAM): Managed enterprise configuration payloads (such as background hex codes, notification headers, and support phone numbers) broadcasted by an EMM console via RestrictionsManager are parsed purely in temporary volatile memory to render the UI. No records are written to persistent databases or transmitted off-device.
  • No Interactivity: Collects no user input, keystrokes, form submissions, or diagnostic telemetry.
Framework Default

Future LabWorx Utilities

Unless accompanied by an explicit standalone privacy addendum, any future utilities released by LabWorx inherit these baseline policies: strictly offline execution, zero outbound network traffic, zero third-party telemetry libraries, and private sandbox storage exclusively.
